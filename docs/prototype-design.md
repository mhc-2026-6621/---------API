## 1. プロダクト概要

### 1.1 サービス名

**Asset Finance Checkout API**（仮称）

### 1.2 コンセプト

国内B2B EC上で高額アセット（建機・産業機械等）の購入時に、リース/割賦ファイナンスを「EC決済のように」組み込めるAPIプロダクト。

「Quote-to-Finance」の全フローをカバーする：

```
商品ページ → 月額試算 → 仮審査 → 本審査 → 電子契約 → 納品/検収 → 販売店支払 → 月額請求 → 満了処理
```

### 1.3 対象ユーザーと提供価値

| ユーザー | 役割 | 提供価値 |
|---------|------|---------|
| 買い手企業 | 中小企業・個人事業主・工場・建設会社等 | 高額設備を月額で導入。商品詳細画面からそのまま試算・仮審査 |
| EC事業者/販売店 | 高額アセットを販売するB2B EC事業者 | ファイナンス導線で成約率向上。検収後に一括支払を受領 |
| ファイナンス提供者 | リース会社・割賦販売会社の審査担当 | API経由でアセット/法人/販売店情報を取得。リスク評価・ステータス管理 |

### 1.4 対象アセットカテゴリ

- 中古建機（油圧ショベル等）
- フォークリフト
- 工作機械（マシニングセンタ等）
- 産業機械
- 業務用厨房機器
- 冷凍冷蔵設備
- ロボット・搬送設備

## 2. 技術スタック・アーキテクチャ

### 2.1 技術スタック

| 層 | 技術 | 備考 |
|---|------|------|
| フレームワーク | Next.js 14 (App Router) | TypeScript |
| UI | React 18 | クライアントコンポーネント中心 |
| スタイル | Tailwind CSS | B2B金融調のカラーパレット |
| UIコンポーネント | shadcn/ui | Button, Card, Dialog, Table, Badge, Tabs等 |
| モックAPI | Next.js Route Handlers | `/app/api/` 配下 |
| データストア | TypeScriptオブジェクト/JSON | ランタイムインメモリ（再起動でリセット） |
| 外部依存 | なし | 外部API・外部DB不要 |
| 認証 | なし | ロール切替はヘッダーのセレクターで実現 |

## 3. ディレクトリ構成

> 詳細は [docs/folder-structure.md](folder-structure.md) を参照してください。
> 「このファイルはどの画面で使うか」「探したいものはどこにあるか」が一目でわかる構成です。

### 3.1 設計方針

| 方針 | 説明 |
|------|------|
| 画面ごとにまとめる | `app/` 配下は画面（URL）と1対1対応。画面専用の部品は `_components/` に同居 |
| API は画面と分離 | `app/api/` 配下にモックAPI。画面コードとは独立 |
| 業務ロジックは `lib/` | 月額試算・審査判定などの計算処理。画面にもAPIにも依存しない |
| モックデータは `data/` | トップレベルに置き、一箇所に集約 |
| 共通部品は `components/shared/` | 複数画面で使う部品だけ |
| 型定義は `types/` | ドメインごとに分割 |

### 3.2 全体概要

```
asset-finance-checkout/
│
├── app/                         … 画面（ページ）と API ルート
│    ├── marketplace/            …   🛒 商品一覧・詳細（買い手向け）

### 3.3 画面専用部品の配置ルール

画面でしか使わない部品は、その画面フォルダ内の `_components/` に置く：

```
app/marketplace/

  ├── _components/                      … この画面でだけ使う部品
  │    ├── AssetCard.tsx                …   商品カード
  │    ├── AssetCardList.tsx            …   商品カード一覧
  │    └── AssetSearchFilter.tsx        …   商品検索フィルター
  └── assets/[assetId]/
       ├── page.tsx                     … 商品詳細画面
       └── _components/
            ├── AssetInfoSection.tsx     …   商品情報セクション
            └── MonthlyPaymentSimulator.tsx … 月額試算シミュレーター
```

> `_` プレフィックスは Next.js App Router でルーティング対象外になる仕組みを利用。

ファイル名は「日本語の業務用語と1対1対応する英語名」を採用：

## 4. 画面設計

### 4.1 共通レイアウト

```
┌──────────────────────────────────────────────────────────────────┐
│  [Logo] Asset Finance Checkout API    [Marketplace] [申込管理]    │
│                                    [販売店] [管理者]  ロール:[▼ Buyer] │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│                        メインコンテンツ                             │
│                                                                  │
│                                                                  │
│                                                  ┌──────────┐   │
│                                                  │ </> API  │   │ ← トグルボタン
│                                                  └──────────┘   │
├──────────────────────────────────────────────────────────────────┤
│  ⚠ 本画面はPoC用モックであり、実際の審査結果ではありません          │
└──────────────────────────────────────────────────────────────────┘
```

**ヘッダー要素：**
- ロゴ + サービス名
- ナビゲーション（ロールに応じて表示項目変更）
  - Buyer: Marketplace / 申込管理
  - Merchant: Marketplace / 販売店ダッシュボード
  - Finance Admin: 管理者ダッシュボード / 全申込一覧
- ロール切替セレクター（右端）

**フッター要素：**
- PoCモック注意表記（全ページ共通）

**API Debug Panel（トグル式）：**
- 画面右下にフローティングボタン `</> API` を配置
- クリックで右サイドからスライドインするドロワーパネルを表示
- パネル内容：直近のAPIコール履歴（メソッド、エンドポイント、Request、Response、ステータスコード、レスポンスタイム）
- 閉じるボタンで非表示に戻る
- ロールに関わらず全画面で利用可能

**計算ロジック（`lib/monthly-payment-calc.ts` で実装）：**

```
1. baseRate = カテゴリ別基本レート
     used_construction_equipment: 5.8%
     forklift: 5.2%
     machine_tool: 6.2%
     kitchen_food_equipment: 6.5%

2. creditAdjustment = creditTier別調整
     A: -0.5%
     B: 0%
     C: +1.2%

3. usedAssetAdjustment = 中古資産は +0.4%

4. inspectionAdjustment = 点検レポートなしは +0.3%

5. annualRate = baseRate + creditAdjustment + usedAssetAdjustment + inspectionAdjustment

6. monthlyRate = annualRate / 12

7. residualValue = assetPrice * residualValuePercent / 100

8. principal = assetPrice - downPayment - PV(residualValue)
   PV(residualValue) = residualValue / (1 + monthlyRate)^termMonths

9. baseMonthlyPayment = principal * monthlyRate / (1 - (1 + monthlyRate)^(-termMonths))

10. insuranceMonthlyFee = includeInsurance ? round(assetPrice * 0.008 / 12) : 0

11. maintenanceMonthlyFee = includeMaintenance ? round(assetPrice * 0.015 / 12) : 0

12. totalMonthlyPayment = baseMonthlyPayment + insuranceMonthlyFee + maintenanceMonthlyFee
```

**仮審査ロジック（`lib/pre-screening-judge.ts` で実装）：**

```
スコア算出:

[信用スコア (creditScore)] 100点満点
  - 法人年数 (currentYear - establishedYear)
    ≥10年: +25pt / 5〜9年: +15pt / 3〜4年: +5pt / <3年: 0pt
  - 年商レンジ
    300m_over: +20pt / 100m_300m: +15pt / 50m_100m: +10pt / under_50m: +5pt
  - 決算書提出可: +15pt
  - 代表者保証あり: +10pt
  - 売上データ提出可: +5pt
  - 業種リスク（建設: 0pt / 製造: +5pt / 物流: +3pt / 飲食: -5pt）

[アセットスコア (assetScore)] 100点満点
  - 製造番号あり: +20pt / なし: 0pt
  - 状態ランク (A+: +25pt / A: +20pt / B+: +15pt / B: +10pt / C: +5pt)
  - 年式 (5年以内: +20pt / 10年以内: +10pt / 10年超: +5pt)
  - 点検レポートあり: +15pt
  - 所有権チェック verified: +10pt
  - 担保権チェック clear: +10pt

[販売店スコア (sellerScore)] 100点満点
  - 認定済み (certified): +50pt
  - リスクグレード (A: +30pt / B: +20pt / C: +10pt / D: 0pt)
  - 過去実績あり: +20pt

[総合スコア (totalScore)]
  = creditScore × 0.5 + assetScore × 0.3 + sellerScore × 0.2

判定:
  - totalScore ≥ 70 かつ 全同意あり かつ 製造番号あり かつ 販売店認定済み
    → pre_approved
  - totalScore 45〜69 または 個別条件未充足
    → manual_review
  - totalScore < 45 または 反社チェック同意なし
    → declined

追加ルール:
  - 希望金額 > 30,000,000 → 自動的に manual_review（スコアに関係なく）
  - 法人設立3年未満 → manual_review
```

## 9. ビジネスロジック設計

### 9.1 月額試算計算 (`lib/monthly-payment-calc.ts`)

```
入力: QuoteRequest
出力: QuoteResponse

処理フロー:
1. カテゴリから基本レートを取得
2. 信用ティアによる調整
3. 中古資産の場合 +0.4%
4. 点検レポートなしの場合 +0.3%
5. 最終年率を算出
6. 月利 = 年率 / 12
7. 残価の現在価値を算出
8. ファイナンス対象額 = 物件価格 - 頭金 - 残価現在価値
9. PMT計算で月額基本支払額を算出
10. 保険料月額 = 物件価格 × 0.8% / 12（オプション）
11. メンテナンス月額 = 物件価格 × 1.5% / 12（オプション）
12. 合計月額 = 基本支払額 + 保険料 + メンテナンス
```

**カテゴリ別基本レートテーブル（`lib/rate-table.ts`）：**

| カテゴリ | baseRate |
|---------|----------|
| used_construction_equipment | 5.8% |
| forklift | 5.2% |
| machine_tool | 6.2% |
| kitchen_food_equipment | 6.5% |
| industrial_machinery | 6.0% |
| refrigeration_equipment | 6.3% |
| robot_conveyor | 5.5% |

### 9.2 仮審査判定 (`lib/pre-screening-judge.ts`)

セクション7.2.4に記載のスコアリングロジックに従う。

### 9.3 リスクスコア計算 (`lib/risk-score-calc.ts`)

```
入力: Buyer, Asset, Seller
出力: RiskAssessment

処理:
1. creditScore = calcCreditScore(buyer)
2. assetScore = calcAssetScore(asset)
3. sellerScore = calcSellerScore(seller)
4. totalScore = creditScore * 0.5 + assetScore * 0.3 + sellerScore * 0.2
5. warningFlags = collectWarningFlags(asset, buyer, amount)
6. result = determineResult(totalScore, consents, asset, seller, amount)
```

## 12. 実装方針・制約

### 12.1 実装方針

| 項目 | 方針 |
|------|------|
| データ永続化 | インメモリ（TypeScript配列）。再起動でリセット。プロトタイプとして十分 |
| 状態管理 | React useState / useContext。状態管理ライブラリ不要 |
| APIコール | fetch API を使用。SWR等のキャッシュライブラリは不要 |

| エラーハンドリング | 最小限。APIは常にモックデータを返すため |
| テスト | 不要。PoCプロトタイプのため |
| 国際化 | 不要。日本語のみ |
| アクセシビリティ | shadcn/ui標準のa11yのみ |
| デモ用プリフィル | 申込フォームに「サンプル入力」ボタンを配置 |

### 12.2 制約・注意事項

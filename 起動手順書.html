エンベデットリースAPI　起動手順書

配布フォルダをセットアップし、ローカル環境でサービスを起動するまでの手順を記載しています。

概要

本サービスは Next.js v14.2.15 で実装されたWebアプリケーションです。外部データベース・クラウドサービス・認証サーバーへの依存はなく、ローカル環境のみで完全に動作します。

セットアップの大まかな流れは以下のとおりです。

  1. Node.js（実行ランタイム）を対象PCにインストール ─ 初回のみ
  2. npm ci で依存パッケージを取得 ─ 初回のみ
  3. npm run dev で開発サーバーを起動
  4. ブラウザで http://localhost:3001 にアクセス
💡
2回目以降は起動コマンドのみで動作します Node.jsのインストールと npm ci によるパッケージ取得は初回セットアップ時のみ必要です。

2Node.jsのインストール

ℹ️
Node.js について V8エンジンを搭載したJavaScriptランタイムです。Next.jsをはじめとする多くのサーバーサイドフレームワークの実行基盤となります。Node.jsがインストール済みの場合は「インストールの確認」のみ実施してください。

インストール手順

  1. 公式サイトを開きます: https://nodejs.org/
  2. サイトに大きく表示される 「LTS（推奨版）」 のボタンをクリックしてインストーラーをダウンロードします。
    ※ LTS とは Long Term Support（長期サポート版）の略で、安定性が高い公式推奨バージョンです。
  3. ダウンロードした .msi ファイルをダブルクリックして実行します。
  4. インストーラーの画面では、すべてデフォルト（既定値）のまま「Next」を押し続けてインストールを完了させてください。

インストールの確認

インストール完了後、新しく PowerShell を開き（スタートメニューで「PowerShell」と検索）、以下の2行を1行ずつ入力して Enter を押します。

▼ PowerShell に貼り付けて実行

node -v
npm -v
✅
正常にインストールされている場合の出力例 v20.x.x のようなバージョン番号が2行表示されます。
「認識されていない」「コマンドが見つからない」が表示された場合は、PowerShellを閉じてから開き直してください（インストール直後はPATHへの反映のため再起動が必要なことがあります）。

3配布フォルダの構成

配布対象のフォルダは以下です。

エンベデットリースAPI/

実行時に自動生成されるフォルダ（配布不要）

下記のフォルダはビルドまたはサーバー起動時に自動生成されます。配布パッケージへの同梱は不要です。

フォルダ名何が入っているか
app/node_modules/外部パッケージ一式。npm ci で再取得できます。
app/.next/ビルドの中間生成物。npm run dev 実行時に自動生成されます。
app/test-results/過去のテスト結果。なくても問題ありません。
app/coverage/テストカバレッジレポート。なくても問題ありません。
💡
転送サイズについて 上記フォルダを除外した状態では数MB程度です。含めた場合は node_modules/ だけで数百MBになります。

4初回セットアップ（パッケージの取得）

ℹ️
この手順は初回セットアップ時のみ必要です package-lock.json に記録された依存関係を正確に再現して取得します（npm install と異なり、lockfileを上書きしません）。インターネット接続が必要です。

手順

PowerShell を開き、配布フォルダ内の app ディレクトリへ移動します。パスは実際の配置先に合わせて読み替えてください。

▼ 例：デスクトップにコピーした場合

cd "C:\Users\ユーザー名\Desktop\エンベデットリースAPI\app"

移動できたら、以下のコマンドを実行します。

▼ パッケージ取得（初回のみ）

npm ci

※ 通信環境によっては数分かかります。

✅
正常完了時の出力 added ○○○ packages と表示されプロンプトに戻れば完了です。
⚠️
npm ci が失敗する場合 Node.jsのバージョン不一致などが原因であることが多いです。npm install で代替できます。 
npm install

5起動してブラウザで開く

セットアップ済みの app フォルダで、以下のコマンドを実行します。

▼ 開発サーバーの起動

npm run dev
ℹ️
起動完了の確認 ターミナル出力に Local: http://localhost:3001 が表示されれば開発サーバーの準備完了です。
このPowerShellプロセスがサーバーを維持しているため、ウィンドウを閉じると同時にサーバーが停止します。

ブラウザで開く

Microsoft Edge または Google Chrome を開き、アドレスバーに以下を入力して Enter を押します。

http://localhost:3001

※ localhost はループバックアドレス（127.0.0.1）の別名です。外部ネットワークへは公開されません。

6正常に動いているか確認する

ブラウザに画面が表示されていれば正常です。追加の検証として、テスト実行およびプロダクションビルドを行うことができます。いずれも開発サーバーの起動有無に関係なく実行可能です。

テストの実行

▼ smoke test（基本的な構成チェック）

cd "C:\Users\ユーザー名\Desktop\エンベデットリースAPI\app"
npm test
✅
正常完了時の出力pass 2 と表示されれば正常です。

ビルドの確認（任意）

本番向けのビルドが問題なく完了するかを確認します。数分かかります。

▼ プロダクションビルド

npm run build
✅
正常完了時の出力Compiled successfully と表示されれば正常です。

7停止方法

アプリを起動しているPowerShellウィンドウをクリックしてアクティブにし、Ctrl キーを押しながら C キーを押してください。

次回起動時は手順5の npm run dev だけで再起動できます。

8本番相当で確認したい場合

ℹ️
通常のデモ確認は npm run dev で十分です
本番ビルド（npm run build → npm run start）は、最適化済みバンドルで動作を検証したい場合に使用します。

▼ 本番ビルドして起動

npm run build
npm run start

アクセス先は開発サーバーと同じです。

http://localhost:3001

9トラブルシューティング

「npm は認識されていません」と表示される

原因：Node.jsのインストールが完了していないか、PowerShellをインストール前から開いたままになっています。

対処：Node.jsを再インストールし、PowerShellを一度完全に閉じてから新しく開き直してください。

ブラウザで画面が開かない（「接続できません」）

原因：アプリがまだ起動していない、または起動に失敗しています。

対処：PowerShellに Local: http://localhost:3001 と表示されているか確認してください。エラーメッセージが出ている場合は次の項目を参照してください。

「ポート3001がすでに使用中」と表示される

原因：別のPowerShellで同じアプリが起動中です。

対処①：既存のPowerShellウィンドウを探し、Ctrl + C で停止してから再度 npm run dev を実行してください。

対処②：どうしても停止できない場合は、ポート番号を変えて起動できます（アクセス先URLも変わります）。

▼ ポートを変えて起動する例（3011番を使用）

npx next dev -p 3011

この場合のアクセス先は http://localhost:3011 です。

画面が古い状態で止まっている・レイアウトが崩れている

原因：ビルドキャッシュが古い状態で残っています。

対処：アプリを一度停止し（Ctrl + C）、以下のコマンドでキャッシュを削除してから再起動してください。

▼ キャッシュ削除して再起動

Remove-Item .next -Recurse -Force
npm run dev

パッケージの取得（npm ci）が途中で止まる・失敗する

原因：ネットワーク状態やキャッシュの問題が考えられます。

対処：node_modules フォルダを削除してから再実行してください。

▼ node_modules を削除して再取得

Remove-Item node_modules -Recurse -Force
npm ci

補足・よくある質問

インターネット接続は必要？ 起動・デモ確認だけなら不要です。パッケージ取得（npm ci）のときだけ必要です。
データはどこに保存されている？ アプリ内のモックデータ（サンプルデータ）を使っています。実際のDBは使っていません。
何か機密情報が含まれている？ このPoCにパスワードや秘密情報（環境変数）は含まれていません。
設計書や仕様書はどこ？ フォルダ内の docs/ に格納されています。docs/README.md が入口です。
